# PlaceItem persistence

See the [patch table](../docs/patches.md) for status and selection details.

`PlaceItem` and `PlaceItemCell` can create a reference in a cell the player has not visited. The
retail insertion path initializes the reference and adds it to the cell, but does not mark that
cell as changed. The save writer can therefore omit the cell and lose the new reference.

## What the patch changes

Both commands share an Xbox helper at `0x00138AA0`. Immediately before its call to
`Cell::addReference` at `0x00138C17`, a payload wrapper sets bit `0x02` at offset `0x08` in the
destination cell and then tail-calls the original method. This matches the dirty mark used by the
cell save path and leaves reference creation unchanged.

## What remains

The equivalent Xbox path and missing dirty mark are established statically. A control-versus-patch
test still needs to place an object in an unvisited cell, save without visiting it, reload, and
confirm the object exists.
